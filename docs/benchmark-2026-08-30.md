# 10,000 篇与六语 60,000 页静态构建基准（2026-08-30）

命令：

```sh
npm run benchmark
```

环境：Darwin 25.5.0 arm64、Node v24.14.0、Pagefind Extended 1.5.2。本次临时生成 10,000 篇单语言逻辑文章，结束后已自动删除 `.benchmark-content/` 和 `.benchmark-site/`，没有把语料或产物加入仓库。

| 项目 | 结果 |
|---|---:|
| 逻辑文章 / 详情页 | 10,000 / 10,000 |
| 临时语料生成 | 0.61 秒 |
| 静态 HTML 构建 | 4.74 秒 |
| Pagefind 索引 | 4.77 秒 |
| 总计（不含 npm install） | 10.11 秒 |
| 含 Pagefind 的 artifact | 110.36 MiB |

同一环境随后运行了更严格的六语完整规模测试：

```sh
npm run benchmark -- --six-locales
```

| 项目 | 结果 |
|---|---:|
| 逻辑文章 / 详情页 | 10,000 / 60,000 |
| Pagefind 扫描的 HTML | 72,012 |
| 临时语料生成 | 3.72 秒 |
| 静态 HTML 构建 | 28.45 秒 |
| Pagefind 索引 | 10.44 秒 |
| 总计（不含 npm install） | 42.61 秒 |
| 含 Pagefind 的 artifact | 722.37 MiB |

两个测试的临时语料和产物都已自动删除，没有加入仓库。这是短合成语料的本机容量基线，不代表 GitHub Actions 或真实长文的最终时间/体积。六语 60,000 页目前低于项目 750 MiB 预警线和 850 MiB 阻断线，但余量已经有限；真实长文、未来脚本和更多媒体会继续增加体积。

因此长期策略是：核心内容优先提供六语版本，长尾内容按实际需求翻译；所有译文共享同一份媒体。接近 3,000–5,000 篇逻辑内容、完整构建接近 8 分钟、产物接近 750 MiB 或媒体仓库接近 800 MiB 时，应在 GitHub Actions 同等级环境再次运行六语基准并重新评估。

确定性检查连续执行了两次干净构建。`build:static` 的文件清单与 SHA-256 汇总均为：

```text
3a2e1dd479eb1ecc3c5f71ffe2643c305fc050152e2fa17e3b04483336ba66a2
```

包含 Pagefind 的两次完整 artifact 汇总不同；Pagefind 1.5.2 的内部索引产物存在非确定字节差异，因此确定性门槛目前严格覆盖生成 HTML、RSS、sitemap 与公共资源，Pagefind 用版本固定、页面数、语言数和功能校验控制。HTML 中没有写入构建时间。
