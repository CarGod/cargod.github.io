FanFan Cards · Privacy

Privacy Policy

Effective August 26, 2026 · Last updated October 20, 2026

ON THIS PAGE OverviewData processedThird-party transfersRetention and deletionSecurity and permissionsContact

Overview

FanFan Cards is a local-first Chrome extension. The developer does not operate a server that receives extension user data, does not use advertising, analytics, or tracking services, and does not sell user data.

Without an AI provider configured, lookups and translation go through the Google Translate endpoint; with one configured, they go to the provider you chose. Data is sent to a third party only when you actively look up, translate, turn on captions or AI listening, choose how settings are synced, or turn on GitHub sync.

Data the extension processes

  • Website content and page information: when you actively select, explain, or translate content, the extension reads the selected text, the nearby sentence or paragraph, the page title, and the page URL. Paragraph and full-page translation read visible text on the current page.
  • FanFan mode and saved-word highlights: when you enable FanFan mode, the extension scans visible text on the current page and matches it against the word library stored in your browser. Matching and highlighting happen entirely on-device. Page content is not sent to an AI provider, the developer, or another third party.
  • YouTube captions: when you turn on bilingual captions in the YouTube player, or have automatic captions enabled, the extension reads the current video's caption-track list and caption text. Caption requests are made from the page context to youtube.com, so they carry the browser's existing YouTube cookies in the same way as the page's own requests. The extension does not read, store, or transmit those cookies. A one-time validation parameter generated by the player is used only for the immediately following caption request; it is not retained or sent to the developer or another third party.
  • Captions on other video sites: when you turn on bilingual captions for a video, have automatic captions enabled, or pick the caption area on a player, the extension reads that video's caption track or the text in that area for translation. A picked area is stored on this device only, as a page selector. On bilibili.com, the extension selects captions in the player's own caption menu and then fetches the caption file the player has already loaded a second time (same address, without account cookies). It calls no other bilibili endpoint, and bilibili account information is not sent anywhere.
  • AI listening: off by default and must first be allowed in video settings. Only after you then click “Start AI listening” on a player does the extension read that player's audio track; the microphone is never used. Speech recognition runs locally in the browser, and audio segments are kept in memory only — never uploaded, saved to the word library, or synced. The recognized text, the last few sentences of context, and the page title are sent directly to the AI service you configured, for correction and translation. Turning the setting off, stopping listening, leaving the page, or switching videos releases the audio and the local model session.
  • Input-box translation (triple space): the extension listens to keystrokes in web page input fields only to detect three consecutive spaces; when triggered, the existing text in that field is sent to your chosen AI provider for translation and replaced in place. Input is never logged or stored.
  • Provider failure recovery: only after you choose a temporary service does the extension send a fixed short text (containing no page content) to the original model in the background to check whether it has recovered. Concurrent checks are merged and each lasts at most 20 seconds; on recovery you are only notified and decide whether to switch back. The failure state and the temporary choice stay on this device; keys are not copied and nothing is written to configuration sync. While Google is used temporarily, text to translate goes directly to Google, and AI listening keeps local recognition without AI correction.
  • Learning data: saved words, explanations, source sentences and URLs, review history, learning activity, and user settings.
  • Authentication information: AI service API keys entered by the user and, if GitHub sync is enabled, a GitHub token entered by the user.

Cards, review history and learning activity are stored in your own browser through chrome.storage.local. First-time setup starts by having you choose a configuration folder; once authorized, settings, AI API keys and the GitHub token are saved to a configuration file in that folder. You can instead keep settings on this device only, or actively turn on browser account sync — only then are they written to the browser-managed chrome.storage.sync, which the browser syncs across devices signed in to the same account; where sync is unavailable they stay on this device. Existing installations keep the method they already chose. You can switch to local-only under Configuration sync.

Before each update, the extension keeps a copy of the settings from before the update in chrome.storage.local on this device (at most 3 copies, including AI API keys and the GitHub token), used only to restore lost settings from the settings page after an update. The copy is not written to the configuration file or browser sync, not exported, and not sent anywhere. The developer cannot access this local data or your browser sync storage.

When data is sent to third parties

The extension offers the following transfers (network requests use HTTPS, except a custom local development endpoint):

  1. Without an AI provider configured (the default after installing), the selected text, its sentence, translated paragraphs and subtitle text are sent directly to the Google Translate endpoint (translate.googleapis.com), with no relay; Google's handling of that data is governed by Google's privacy policy.
  2. After you choose and configure an AI provider, the selected text, required context, page title, and URL are sent directly to that provider (Anthropic, OpenAI, DeepSeek, Google Gemini, or a compatible API endpoint you provide) to generate an explanation or translation. API keys in AI requests are sent to the corresponding provider; for keys in configuration backups, see items 4 and 5. When you turn on bilingual captions (on YouTube or other sites), the current caption text and page title are sent in the same way to generate the translation. When you trigger translation with three spaces in an input field, the existing text in that field is sent the same way.
  3. After you actively enable GitHub sync, word cards, source information, review history, and learning activity are sent to a repository in your own GitHub account; the token in GitHub requests is sent to the GitHub API. Restoring settings never commits settings or keys to the word repository.
  4. If you choose automatic configuration sync through your browser account, settings, AI API keys and the GitHub token are written to the browser's sync storage. Whether they travel between devices depends on your browser sign-in and sync settings, and is handled by Google, Microsoft, or the respective browser provider. The extension adds no separate passphrase or application-level encryption and cannot confirm when the cloud upload completes.
  5. You can export a JSON configuration file containing the full keys, or authorize the extension to read and write FanFan Cards/config.json in a folder you choose. If you choose an iCloud Drive folder, Apple's system services handle syncing it; the extension only touches the local file you authorized. The folder handle is stored on this device only; a new device must choose the folder again, and expired permission must be granted again.

The first time AI listening is used, the extension downloads fixed-version speech model data from Hugging Face and caches it in the browser for reuse. The model download service receives no audio, transcribed text, or AI keys — only the download request and ordinary network connection information. The inference code and WebAssembly ship inside the extension; no remote code is downloaded or executed. The model cache is cleared by removing the extension's data or uninstalling it.

The developer does not receive this data through a relay server. A third party's handling of the data is governed by the terms and privacy policy between you and that provider.

Data retention and deletion

Local data remains until you clear it in the extension, remove the extension's data, or uninstall the extension. From the settings page you can export the configuration JSON (which contains keys but not cards or review history) and clear caches or all cards. Cards and review history are restored through your own GitHub repository.

Data synced to GitHub is governed by the settings and actions of your own GitHub repository and can be deleted by you on GitHub. You manage and delete the configuration file in the folder you chose; browser sync copies are managed by your browser account and sync settings. Switching to local-only stops this device from syncing further but does not delete copies already on other devices or in the cloud.

Security and minimum permissions

The extension does not load or execute remote code. External requests use HTTPS; only a local development endpoint may use http://localhost. Access to a custom API endpoint is requested for that specific host only after you click “Test connection.”

The extension injects a script into the page context on youtube.com. It is used only to read public video and caption-track information from the player, record the one-time validation parameter described above, and make the same-origin caption request. The script cannot access extension APIs, does not read other page data, and does not communicate with a server operated by the developer.

The extension's use of information follows the Chrome Web Store User Data Policy, including its Limited Use requirements:

The use of information received from Google APIs will adhere to the Chrome Web Store User Data Policy, including the Limited Use requirements.
